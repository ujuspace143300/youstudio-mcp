# 스케치코미디 · 완성 확인

기계 게이트는 [정답지.json](정답지.json)이 정본이다. 여기는 **기계가 못 잡아서 사람이 봐야
하는 것**(정답지 「사람확인」 6항목)과, 검수에서 실제로 터졌던 사고의 맥락만.

## 사람이 보는 순서

1. ★**첫 3초** — 훅이 박혔는가. 상황 설명으로 열렸으면 계획부터 틀린 것이다.
2. ★**나레이션 구간** — 대사와 겹치지 않는가. 겹치면 패딩 부족(정답지 G-나레이션이 놓친
   것이니 게이트 구멍을 메운다).
3. ★**끝** — 칼같이 떨어지는가. 여백이 남았으면 하드컷 규칙 위반.
4. **얼굴** — 화면이 굳거나 배경을 잡지 않는가(렌더 로그 「얼굴 0」 확인).
5. **자막** — 실제 기기 비율에서 UI 버튼에 가리지 않는가.
6. **웃긴가** — 검사기는 이것을 못 본다. 나레이션 톤이 건조한가도 사람 몫.

라우드니스 -14 LUFS 목표(규격 audio) · 나레이션은 대사보다 낮게 들려야 한다.

## 싱크 사고 이력 — 왜 이 순서인가

- 모델 자막 시각은 **추정**이라 줄마다 -1.1~+1.6초로 어긋나고 중앙이 +0.12초 — 「전체가
  밀린」 게 아니라서 일괄 보정으로는 못 고친다. 사람 눈에는 「미묘하게 밀린다」로 보인다.
  → asr(실측) + sync(줄 단위)가 답이다.
- `silencedetect` 로는 발화 시작점을 못 잡는다 — 대사가 빠르게 이어지는 채널이라 41초에
  무음이 13곳뿐이었다. 31줄을 13곳에 맞출 수는 없다.
- ★★**정렬이 안 맞으면 손대지 말고 멈춰라**(정답지 G-싱크맞물림 stop). ASR 단어 키를
  잘못 읽어 0자가 나왔는데 그대로 진행돼 31줄이 통째로 뭉개진 사고가 근거다.
- 구간을 고쳤으면 자막·나레이션을 다시 뽑는다 — 시각이 어긋난 채로 남는다.
