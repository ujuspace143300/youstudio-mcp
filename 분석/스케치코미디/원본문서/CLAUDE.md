# sketch2 — 불변식

스케치 코미디 롱폼을 잘라 숏폼으로 만든다. **규격의 정본은 「마스터 지침서 3.11」**이고
`config.json` 이 그것을 값으로 옮겨 적은 것이다. 코드는 그 값을 실행만 한다.

```powershell
& $PY vh.py step sketch2/projects/<편>.json     다음 행동 + 그 단계의 함정
& $PY vh.py check sketch2/projects/<편>.json    검사 (공짜) + 통과 기록
```

★검사를 통과하지 않은 편은 제작이 막힌다. 건너뛰려면 `--force`.

## ★★sketch 와 무엇이 다른가 — 섞지 마라

소재는 같지만 **다른 채널이다.** 한쪽 규칙을 다른 쪽에 쓰면 둘 다 무너진다.

| | `sketch` | **`sketch2`** |
|---|---|---|
| 근거 | 「먹기전에」 10편 실측 | **「마스터 지침서 3.11」** |
| 화면 | 5층 분리 (영상이 가운데 상자) | **전체화면 + 오버레이** |
| 나레이션 | **없음** (배우 대사가 전부) | **있음** — 제3자 나레이션이 핵심 장치 |
| 구조 | `punch` 세기순, 시간순 유지 | **5-Phase** (Hook→Context→Ping-Pong→Climax→Punchline) |
| 상단 | 검은 제목 2줄 | **반투명 타이틀바 + 서브 해시태그** |
| 길이 | 50~110초 | **40~50초** (최대 75) |
| 출처 | 화면 맨 아래 상시 노출 | 채널 워터마크 |
| 돈 | 렌더 공짜 (Gemini 만) | **TTS 요금이 나간다** |

## 이 채널의 불변식

- ★★★**밀도가 구조를 이긴다.** 완성 길이 ÷ 원본에서 펼친 범위가 **35~80%** 여야 한다.
  같은 소재로 견줘 46% 인 편이 18% 인 편을 이겼다 — **5-Phase 딱지는 18% 쪽이 더
  정확했는데도** 그렇다. 넓게 퍼뜨리면 대목 사이 맥락이 끊긴다.

- ★★**5-Phase 가 기승전결이다.** 조각마다 `phase` 를 매긴다. 세기(`punch`)만으로는
  구조가 안 나온다 — sketch 에서 punch 7·8·10·10·9·8·7·9·10 처럼 평평해지는 것을 봤다.
- ★★**첫 3초에 훅이 박혀야 한다.** 상황 설명으로 열지 않는다. 필요하면 **순서를 바꾼다**
  (sketch 와 갈리는 지점 — 그쪽은 시간순을 지킨다).
- ★★**나레이션은 건조하고 무심하게.** 화면 속 인물의 오버하는 연기와 대비를 이룬다.
  대사보다 낮은 음량(-6~-9dB)이고, 자막 색을 달리해 실제 대사와 구분한다.
- ★**나레이션 길이만큼 원본 화면을 확보한다**(Padding 법칙). 읽을 시간보다 배정된
  구간이 짧으면 다음 대사가 겹쳐 튀어나온다.
- ★★**마진을 반드시 남긴다.** 꼬리 3~5프레임 · 시각적 액션 버퍼 15~30프레임 ·
  숨고르기 0.5~1.5초. **빠른 호흡만 쫓다 내용을 못 알아보게 만들지 마라.**
- ★**끝은 하드컷.** 가장 감정이 폭발한 지점에서 대사가 끝나자마자 0.1초의 여백도 없이.
- ★**제목은 15자 이내, 끝은 `?` `!` `...`.** 「그래서 어떻게 되는데?」를 만들어야 한다.
- **원본 프레임레이트를 100% 따른다.** 마진이 프레임 단위라 fps 가 틀리면 전부 어긋난다.
- **댓글 타임스탬프는 사람들이 실제로 웃은 자리다** — 좋아요 상위 지점을 빠뜨리지 않는다.

## ★한 소재에서 **두 편**을 만든다

스케치 코미디 롱폼에는 웃긴 대목이 보통 두세 군데 있고, **댓글 타임스탬프가 어디인지
알려 준다.** 두 채널에 나눠 올리므로 한 소재를 두 편으로 쪼갠다.

```powershell
& $PY -m s2pipe.plan "<URL>" --slug <id>_A                  # 모델이 알아서
& $PY -m s2pipe.plan "<URL>" --slug <id>_B --focus <초>      # 다른 클러스터
```

같은 원본에서 「당구 사기」와 「헌팅」처럼 **완전히 다른 편**이 나온다.

## 한 편을 만드는 순서

```powershell
& $PY -m s2pipe.plan "<원본 롱폼 URL>"           # 원본 받기 + 5-Phase 로 자르기
#   → projects/<id>.json   ★여기서 사람이 검토한다
& $PY make.py projects/<id>.json --check         # 검사 (공짜)
& $PY make.py projects/<id>.json                 # 굽기 (★TTS 요금)
& $PY -m s2pipe.subs projects/<id>.json          # ★★굽고 나서 자막을 다시 뽑는다
& $PY -m s2pipe.asr  projects/<id>.json          # ★실제 발화 시각 (Speechmatics 요금)
& $PY -m s2pipe.sync projects/<id>.json          # ★★자막 시각을 발화에 맞춘다 (공짜)
& $PY make.py projects/<id>.json --check         # 대본이 바뀌었으니 다시 검사
& $PY make.py projects/<id>.json                 # 다시 굽는다
& $PY -m s2pipe.comments projects/<id>.json --refetch   # 댓글만 다시 (공짜)
```

★★**자막은 반드시 두 번 뽑는다.** 계획 단계 자막은 원본 전체를 보고 낸 것이라
**싱크가 어긋나고 성기다** — 조각을 잘라 붙이면 시각이 통째로 달라지기 때문이다.
`subs` 는 잘라 붙인 `cut.mp4` 만 본다(실측 24줄 → 31줄, 빈 구간 0).

★★★**그래도 「미묘하게 밀린다」** — 모델은 영상을 보고 시각을 **추정**하므로 줄마다
-1.1 ~ +1.6초로 어긋난다. 중앙이 +0.12초라 일괄 보정으로는 못 고친다.
`asr` → `sync` 가 **줄 단위로** 맞춘다. **문구는 모델 것, 시각은 ASR** —
ASR 문구는 오인식이 많아 그대로 쓰면 안 된다(「잭팟」→「책팟」).

## 돈

★**`make.py` 는 TTS 요금이 나간다** — sketch 와 다른 점이다. 나레이션이 이 채널의
핵심 장치라 뺄 수 없다. `--check` 와 `plan` 의 모델 호출은 공짜다(EvoLink 무료 한도).

멀티모달은 **EvoLink 를 먼저 쓴다**(`s2pipe/gem.py`). 순정 Gemini 보다 5~7배 빠르고
503 이 없다. ★`User-Agent` 와 `contents[].role` 이 없으면 각각 403·타임아웃이다.
