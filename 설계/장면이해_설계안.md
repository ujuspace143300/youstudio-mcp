# 장면이해 단계 — 설계안 (보고용, 구현 안 함)

작성 2026-08-16 · 갱신 2026-08-16(Q2 답 반영, B안 채택). 근거: 가족 강제 규칙(`가족인터뷰.md`) "제미나이 멀티모달이 영화 **전체**를 본다". **자리(B안)와 runner 형태(need_input)는 결정됨**, 출력 형식(Q3)은 미결. 구현은 아직 하지 않는다 — Q3 샘플이 오면 `단계상세.md` 에 정식 명세로 옮기고 여기는 근거로 남긴다.

## 0. 한 줄

transcript 뒤에 **장면이해**(scene) 단계를 넣는다. 서버는 **need_input** 으로 멈추고, **사람이 구글 AI Studio 에 원본 영상 전체 + 지침서를 직접 첨부**해(가족 Q2 답) 제미나이가 통째로 본 뒤 내놓은 **사건 목록 + 편집점 타임코드**를 `scene/scene.json` 으로 저장한다. brief 는 이 단계의 **폴백**(`vision_mode: fallback_frames`)이 되고, select 의 "무음 구간 프레임 판정"은 없어지거나 검증용으로 남는다. Files API 자동 업로드는 2차 자동화 후보.

## 1. 어디에 끼우나 — 세 안

| 안 | 순서 | 장점 | 단점 |
| :---- | :---- | :---- | :---- |
| A. brief 앞에 추가 | probe → transcript → **scene** → brief → select … | 기존 단계 손대지 않음 | brief 가 전사만 보고 사건을 또 뽑는다 — 사건 목록이 둘 (충돌·중복) |
| **B. brief 대체 (추천)** | probe → transcript → **scene**(실패·키 없음이면 brief 폴백) → select … | 사건 목록이 하나. brief 코드는 그대로 폴백으로 살아 있음. select 는 입력만 바뀜(사건에 시각 근거·편집점 후보가 붙어 옴) | select ① 의 무음 구간 판정과 역할이 겹침 → select 는 서버 계산만 남기고 판정은 검증용 스위치로 |
| C. brief + select 판정 합침 | scene 이 사건 + 구간까지 확정 | 가족 프로세스와 가장 가까움("대본 + 편집점 한 번에") | 서버 계산(예산·창·역할·게이트)이 제미나이 출력에 끌려감 — HARNESS "조건만 적는다"와 어긋남 |

**결정 2026-08-16: B안 채택.** 이유: 강제 규칙(전체를 본다)을 만족시키면서, "무엇이 참이어야 하는가"(예산·대역·게이트)는 서버에 남는다. 폴백 경로가 명시적이라 키·크레딧이 없을 때도 파이프라인이 멈추지 않되 **폴백임을 지표로 드러낸다**(`vision_mode: full | fallback_frames`).

## 2. 입력 · 출력 · 게이트 후보

**입력**
- 영화 파일 전체 — **사람이 AI Studio 웹에 원본을 그대로 첨부**(Q2 답). 서버는 어느 파일인지(`source.path`)와 첨부할 지침서 목록만 지시한다
- 지침서: 스타일 폴더에서 **이 단계에 필요한 것만** — `구간선택.md`(어떤 장면을 쓰나) + 규격 「구간선택」 숫자 + `facts.json`(크레딧 시작 등 사람이 잰 사실). 나레이션·자막 지침은 주지 않는다(HARNESS 2)
- transcript.json (발화 시각 — 편집점이 발화 중간을 자르지 않게 하는 대조 재료). 프롬프트에 넣지 않고 ② 검증에서만 쓸 수도 있음 — 결정할 것

**출력** `scene/scene.json`
- 사건 목록: `t0/t1`(초) · 요약 · 인물 · 중요도 1~5 · 시각 근거(무엇이 보였나) · 소리 근거 · spoiler 표시 · **편집점 후보**(in/out 초, 왜 여기서 끊나)
- 결말 사건과 `ending_visual_only` 구간을 반드시 포함
- 원본 응답은 `scene/judge_raw.json`, 사용 토큰·비용은 metrics

**지표(metrics)**: 사건 수 · 커버리지(사건이 덮는 시간/전체) · 무음 구간마다 사건 수 · 편집점 수 · 입력 토큰(영상 분) · 비용 · `vision_mode`

**게이트 후보** (수리 지침 붙여서)
| 게이트 | 조건 | 실패 시 |
| :---- | :---- | :---- |
| 타임코드 범위 | 모든 t0/t1 ≤ probe.duration_s, 크레딧 이후 사건 0 (facts.credits_start_s) | 범위 밖 사건 목록과 함께 재호출 지시(모델이 시각을 짐작한 것) |
| 무음 구간 커버 | facts.silent_visual_stretches 각각에 사건 ≥1 | "전체를 본 게 맞는지" 의심 → 해상도/모델 확인 후 재호출 (Full Time #22 노인 반전·#23 결말은 무음 구간에 있었다) |
| 결말 존재 | 마지막 사건이 결말/`ending_visual_only` 를 덮음 | 결말 구간만 다시 묻기 |
| 편집점 ⟂ 발화 | 편집점이 발화 안쪽 0.3s 이내를 자르지 않음(transcript 대조) | 서버가 가장 가까운 발화 경계로 스냅 + 경고 |
| 응답 온전 | finishReason ≠ MAX_TOKENS, JSON 스키마 통과(responseSchema) | maxOutputTokens 올리거나 구간을 나눠 다시 |
| 폴백 표시 | vision_mode=fallback_frames 면 **hard 가 아니라 경고** — 결과에 "폴백" 이 붙어 나간다 | — |

정답지 대역(사건 수·커버리지)은 지무비 19편이 아니라 **우리 실측**으로 시작한다(brief 실측: Full Time 23건·커버리지 값은 brief metrics 참조) → 우리실측.json 에 쌓은 뒤 정답지에 올릴지 결정.

## 3. runner 형태 — need_input + 사람 절차서 (초안)

**형태(결정)**: `scene` ① 호출 → 서버는 `status: need_input` 으로 멈추고 아래 절차서를 `instructions` 로 내려보낸다. 사람이 끝내고 `scene/scene.json` 을 저장하면 ② 호출에서 서버가 검사한다. script(나레이션 집필)·subtitle(번역)과 같은 패턴이라 새 장치가 없다.

**사람이 하는 절차서 (초안 — Q3 샘플이 오면 출력 칸을 확정한다)**

| 순서 | 할 일 | 서버가 채워 주는 것 |
| :---- | :---- | :---- |
| 1 | 구글 AI Studio 를 열고 새 프롬프트를 만든다. 모델은 가족이 쓰는 것과 같은 계열(멀티모달 Gemini) — 고른 모델명은 ② 에서 payload.model 로 적는다 | — |
| 2 | **첨부 ①: 원본 영상 전체** — `source.path` 파일을 그대로 첨부한다(자르거나 프레임으로 바꾸지 않는다 = 강제 규칙) | 파일 경로·크기·길이(probe) |
| 3 | **첨부 ②: 지침서** — `스타일/영화롱폼/구간선택.md`(어떤 장면을 쓰나) + 규격 「구간선택」 숫자(목표 길이·창·역할 규칙) + `facts.json`(크레딧 시작·무음 구간). 나레이션·자막 지침은 첨부하지 않는다 | 서버가 세 조각을 하나의 텍스트로 합쳐 `scene/prompt_attach.md` 로 write_files — 사람은 이 파일 하나만 첨부 |
| 4 | 프롬프트 본문을 붙여 넣는다 — "영상 전체를 보고 사건 목록과 편집점 타임코드를 아래 형식으로" (형식은 Q3 샘플 확보 뒤 확정; 그 전 임시안은 brief 와 같은 사건 스키마 + 편집점 in/out) | `scene/prompt.txt` 로 write_files |
| 5 | 실행 → 응답이 끝까지 왔는지 확인(잘렸으면 이어서 요청) | — |
| 6 | 응답 원문을 **`<workdir>/scene/judge_raw.txt`** 로, 형식대로 정리한 JSON 을 **`<workdir>/scene/scene.json`** 으로 저장한다 (형식이 텍스트면 사람이 그대로 저장하고 ② 가 변환·검사) | 저장 위치·파일명 지시 |
| 7 | `scene` 을 다시 부른다 — payload: `{ scene_path, model, fallback: false }`. AI Studio 를 못 돌렸으면 `fallback: true` → 서버가 brief 를 폴백으로 지시하고 결과에 `vision_mode: fallback_frames` 를 남긴다 | ② 검사·게이트·metrics |

**② 에서 서버가 하는 것**: 타임코드 범위·무음 구간 커버·결말 존재·편집점⟂발화·응답 온전 검사(§2 게이트) → `scene/scene.json` 정리본 + metrics(`vision_mode: full`) → next select.

## 4. (2차 자동화 후보) Files API — 확인 항목

**강등 2026-08-16**: 가족 프로세스는 Files API 를 쓰지 않는다(Q2 답). 아래 표는 **나중에 사람 손을 없애고 싶을 때**를 위한 후보 조사이며, 1차 설계에는 들어가지 않는다. **구글 키의 429(선불 크레딧 소진) 문제는 1차 흐름(AI Studio 웹 첨부)에 해당 없다** — 웹 AI Studio 는 API 키·크레딧과 별개로 사람 계정으로 쓴다.

| 항목 | 아는 것 (지식 시점 기준, **실측 전**) | 확인 방법 |
| :---- | :---- | :---- |
| 키 | **구글 순정** `GEMINI_API_KEY` 만 가능. EvoLink 에는 files 엔드포인트가 없다(참고_runner.md 실측) | 저장됨(2026-08-15). 첫 호출이 429 "prepayment credits depleted" — 이 키가 붙은 프로젝트가 **선불 결제형**이라 무료 티어와 다를 수 있음 → AI Studio 에서 키가 속한 프로젝트·결제 상태 확인 |
| 무료 티어 | Files API 업로드 자체는 무료로 알려져 있고, Flash 계열은 무료 티어(분당·일일 요청 상한)가 있음. 다만 **429 가 난 키로는 무료 티어가 적용되지 않을 수 있다** | 결제 없는 새 프로젝트 키로 `files.upload` + `generateContent` 소량 실측. 상한(RPM/RPD/TPM)을 우리실측에 적음 |
| 파일 크기·보관 | 파일당 상한 **2 GB**, 프로젝트당 20 GB, 업로드 후 **48시간** 보관 후 자동 삭제. 업로드 뒤 `state: PROCESSING → ACTIVE` 를 기다려야 함 | Full Time mp4 크기(probe) 로 1회 실측. 장편(1.5~2h)이 2 GB 를 넘으면 재인코딩(해상도↓) 필요 — 규격에 상한 적기 |
| 영상 길이·토큰 | 1M 문맥 모델 기준 기본 해상도 ≈ 1시간(초당 ≈ 300 토큰: 프레임 1fps + 소리), 저해상도(`mediaResolution` low)면 ≈ 3시간. **gemini-3.5-flash 의 실제 상한은 모른다** | 15.5분 Full Time 으로 토큰·비용 실측 → 장편 예상치 계산. 넘으면 **분할**(전반/후반, 겹침 1~2분)이 필요 — 분할이면 "전체를 한 문맥에서" 가 약해진다는 점을 가족에게 Q2 로 확인 |
| YouTube 소재 | 공개 YouTube URL 은 업로드 없이 `file_data.file_uri` 로 직접 전달 가능(무료 티어 하루 8시간 상한으로 알려짐) | 실측 1회. 우리 source.kind=youtube 와 바로 맞물림 |
| 응답 | responseSchema(구조화 출력)·maxOutputTokens 필수(참고_runner.md — 잘림 사고) · 타임코드는 `MM:SS` 문자열로 받고 서버가 초로 바꾼다(모델이 시각을 문자열로 더 정확히 냄 — 확인 항목) | brief 와 같은 검사 |
| 비용 | 요율 미등록이면 fail-closed(참고_runner.md). 영상 입력 토큰이 크므로 1편당 예상 원가를 metrics 로 | 실측 후 우리실측.json |
| AI Studio 수동 경로 | 가족은 "구글 AI Studio 멀티모달" 이라 표현 — **API 가 아니라 웹 화면에 올렸을 가능성**(Q2). 그렇다면 runner 가 자동으로 못 하고 사람이 올리고 결과 JSON 을 payload 로 넣는 need_input 형태가 된다 | 인터뷰 Q2 답을 기다린다 |

## 5. 서버·runner 에 생기는 것 (구현 전 목록만)

- **1차(결정)**: `scene` 은 script/subtitle 번역과 같은 **need_input** 패턴 — ① 서버가 절차서(§3)를 `instructions` 로 내려보내고 `status: need_input` 으로 멈춘다 → 사람이 AI Studio 에서 받아온 출력을 `scene/scene.json` 으로 저장 → ② 서버가 payload 로 받아 검사(게이트)·정리·metrics. 새 job kind 없음, 키 없음
- 폴백: payload 에 `fallback: true`(사람이 AI Studio 를 못 돌린 경우)면 서버가 기존 brief 지시를 그대로 내리고 결과에 `vision_mode: fallback_frames` 를 박는다
- 규격 「판정」에 `장면이해: {방식: "ai_studio_수동", 모델: (사람이 고른 모델명 기록), 지침서: [구간선택.md, 규격.구간선택], 출력_파일: scene/scene.json}` — 숫자는 실측 뒤
- STEP_ORDER 에 `scene` 삽입(B안: brief 는 폴백일 때만)
- **2차 후보**: job kind `upload`(Files API) + `@file_uri` 재사용 — §4 표 확인 뒤
- 게이트·수리 지침 위 표대로. 테스트: 스모크에 업로드 상태 대기·타임코드 범위·폴백 표시

## 6. 결정 기록 · 미결

**결정 (2026-08-16)**
1. **B안 채택** — 장면이해가 brief 를 대체한다. 기존 brief 코드는 지우지 않고 `vision_mode: fallback_frames` 폴백으로 남긴다(결과물에 폴백 표시가 붙어 나간다).
2. **runner 형태 = need_input** — Q2 답(AI Studio 웹에 원본 첨부, Files API 안 씀). 서버는 절차서를 지시하고 멈춘다. 구글 API 키·크레딧은 1차 흐름과 무관.
3. 첫 실측 소재는 Full Time(15.5분, 전 단계 통과)으로 하고, brief 23건과 나란히 비교해 "전체를 본" 효과(무음 구간 사건·결말)를 숫자로 확인한다.

**미결**
- **Q3 — 제미나이 출력 형식.** 목표는 설명이 아니라 **가족의 실제 출력물 샘플 1개(제미나이가 뱉은 원문 파일)를 확보**하는 것. 그것이 scene.json 스키마·절차서의 "출력 저장" 칸·② 검사 규칙을 정한다. 샘플이 오기 전에는 구현하지 않는다.
- Q1·Q4·Q5 는 이 단계와 무관하게 남아 있음(`가족인터뷰.md`).
