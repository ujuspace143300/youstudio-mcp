# 블롭 서식 쓰기 전에 — 더 싼 길 두 개 검토 (2026-08-19)

지시: 5+① 묶음(prproj 자막 크기·위치·강조)을 하기 전에, **코드 변경이 적은 길**이 있는지 먼저 본다.
결론만 먼저: **검토 1은 된다(0단계 왕복 시험 통과, 2026-08-19). 검토 2는 안 된다.** 잔여 범위는 「한 큐 안 단어 강조」 하나로 좁혀진다.

## 검토 2 — 강조: 도너의 기존 색 런에 배치하는 길 → **불가**

### 실측: 도너 자막 136개 전수

| 항목 | 실측 |
| :-- | :-- |
| 자막 총 | **136개**(V2·V3·V4) |
| 런 개수 | 1런 104 · 2런 24 · 3런 8 |
| **서식이 다른 런을 가진 자막** | **0개** |
| 큐별 크기 종류 | 58 / 94 / 102 / 108 / 117 / 120 / 121 / 157 px — **큐 단위로는 다양** |
| 큐별 폰트 종류 | SDGwanghwamun 79 · Cafe24Dangdanghae 17 · SourceHanSerifK-Bold 15 · SDKwangya 6 · SDGdMyeongjo 5 · SDCharisma 3 · SDBangkakbon 3 · SDComicStencil 2 — **8종 이상** |

**한 큐 안에서는 모든 런의 서식이 같다.** 크기(f1)·읽히는 StyleTable 필드(f2 색·f4·f5·f6·f8·f23·f24)가 런마다 동일했다.

```
item 4265: 「현금 」 102px 색[0,0,0] | 「50달러」 102px 색[0,0,0] | 「를 정직하게 지불한 뒤」 102px 색[0,0,0]
item 4076: 「마이클은 본격적인 」 94px | 「감금 근무」 94px | 「를 시작하고..」 94px
```

### 그런데 눈여겨볼 것 — **런은 이미 강조 단어 경계로 나뉘어 있다**

「현금 」/**「50달러」**/「를 정직하게…」 · 「믿기 힘든 뜻밖의 」/**「정규직 전직」**/「 찬스를..」 — 가운데 런이 정확히 강조 대상 단어다.
즉 **볼케이노도 우리와 같은 구조(런 분할)를 쓰지만, 시각적 차이는 우리가 읽는 필드에 없다.** 셋 중 하나다:
1. 색이 우리가 못 읽는 자리(스트로크·그라데·레이어 중복)에 있다 — **가능성 높음**(흰 자막인데 색이 [0,0,0]으로 읽힌다. 파싱이 미더운 값이 아니다),
2. 이 도너 편에는 실제로 강조가 없다(런만 나뉘어 있다),
3. 강조를 다른 장치(별도 텍스트 레이어)로 낸다.

**어느 쪽이든 결론은 같다** — 견본을 복제해 단어를 배치해 봐야 **보이는 차이가 안 생긴다**. 배치할 「색 런」이 없다.

**→ 기록: `진단일지 §23`.** 서식이 같다면 그 자리에서 런을 나눌 이유가 없다. 그러므로 **강조는 런마다 인코딩돼 있고 우리 파서가 그 필드를 못 읽는 쪽**이 유력하다(흰 자막이 `[0,0,0]` 으로 읽힌다).
그렇다면 단어 강조는 「**StyleTable 새로 쓰기**」가 아니라 「**기존 색 필드를 찾아 복제하기**」다 — 값을 발명하지 않고 도너에 이미 있는 바이트를 옮기는 일이라 훨씬 싸고 안전하다.
**찾는 방법(채택)**: 프리미어에서 **강조가 눈에 보이는 도너 큐**를 하나 특정한다 → 그 큐 블롭에서 **런 사이 바이트를 대조**한다 → 다른 바이트가 나온 자리가 색·크기 필드다. 5단계 착수 전에 한다.

### 다만 하나 건졌다 — **큐 단위 톤 변화는 코드 변경 0으로 가능**

도너에 크기 7종·폰트 8종의 자막 큐가 이미 있다. 조립기가 **견본을 하나만 쓰는 대신 여러 개를 골라 쓰면**, 큐마다 폰트·크기를 바꿀 수 있다(예: 평범한 줄은 SDGwanghwamun 58px, 힘주는 줄은 Cafe24Dangdanghae 117px).
- 되는 것: **줄 전체의 톤 강조**
- 안 되는 것: **한 줄 안에서 단어만 강조** ← 이것이 잔여 범위다

## 검토 1 — 크기·위치: 도너를 프리미어에서 직접 고치는 길 → **된다**(0단계 통과)

### 원리

조립기는 도너 견본의 **서식·위치를 그대로 복제**하고 글자만 갈아 끼운다. 그러므로 **도너 자체의 견본 자막을 새 값으로 고쳐 두면 코드 변경 0으로 반영된다.**

| 바꿀 것 | 지금(도너) | 새 값(규격) |
| :-- | :-- | :-- |
| 나레 자막 크기 | **120px** | **64px** |
| 대사 자막 크기 | **58px** | **44px** |
| 두 자막의 세로 위치 | 각자 다름 | **y 932 한 레인** |

### 0단계 결과 — **통과** (2026-08-19, 실측은 `진단일지 §24`)

한글 프리미어에서 열었다 다른 이름으로 저장했더니:

| 드러난 것 | 우리 대응 |
| :-- | :-- |
| **ObjectID 는 다시 매겨진다**(7311 → 6873 · 견본 3293/4211 → 1708/1790) | 견본을 **속성으로** 찾게 이미 고쳐 뒀다 |
| **UID 는 살아남는다**(새로 생긴 것 0 · 트랙 9개·시퀀스 UID 전부 생존) | 공유 계보·보호 계보를 **UID 에서 유도**하도록 바꿨다 |
| 파라미터 이름이 **한국어로 번역돼 저장된다**(`Source Text` → `소스 텍스트`) | **이름 동의어 표** 도입 |
| 같은 내용 블롭은 두 번 안 쓰고 **해시로 앞의 본문을 가리킨다** | **빈 블롭 해석** 도입 |
| 없어진 것: 캡션 18 · 미사용 서브클립 8 · Color Matte 1 | 우리 8트랙 아이템 수·자막 문구는 **순서까지 동일** |

**재저장한 도너로 조립 → 자기검증 24검사 전부 통과.** 원본 도너 회귀도 통과.
→ **1단계로 간다.** 아래 0단계 절차서는 도너를 다시 손볼 때 되풀이할 수 있게 남겨 둔다.

### 0단계 — 무해 왕복 시험 (사람, 약 10분) **먼저·필수**

**목적**: 프리미어가 저장할 때 우리가 의지하는 번호(ObjectID)와 이름표(UID)를 바꾸는지 본다. **아무것도 고치지 않는다.**

1. **산돌구름 앱을 켠다.** 도너 폰트(SDGwanghwamun · SourceHanSerifK-Bold 등)가 잠겨 있으면 프리미어가 대체 서체로 바꿔 저장할 수 있다.
2. **사본은 이미 만들어 뒀다** → `도너/_도너시험.prproj`. 원본(`도너/볼케이노_FullTime_v26_b05_ppro-v45.prproj`)은 **열지 않는다.**
3. `_도너시험.prproj` 를 **더블클릭**해 연다. 「미디어를 찾을 수 없다」 창이 뜨면 **오프라인(Offline)** 을 누른다 — 영상 파일을 다시 이어 붙일 필요 없다.
4. **아무것도 클릭하지 않는다.** 시퀀스를 열지도, 클립을 고르지도, 창을 옮기지도 마라(창 배치도 프로젝트에 저장된다).
5. **파일 > 다른 이름으로 저장**(Ctrl+Shift+S) → 같은 `도너/` 폴더에 **`_도너시험_저장.prproj`** 로 저장한다.
6. 프리미어를 닫는다. 「다른 이름으로 저장」이므로 `_도너시험.prproj` 는 손대지 않은 상태로 남는다 — 두 파일을 나란히 대조할 수 있다.
7. 「0단계 끝났다」고 알려 준다.

### 내가 대조할 항목 (0단계 저장 후)

| # | 대조 | 통과 기준 |
| :-- | :-- | :-- |
| 1 | **ObjectID 총 개수·최대 번호** | 두 파일이 같다 |
| 2 | **ObjectUID 목록**(계보 GUID) | 집합이 같다 — 하나라도 새로 생기면 재배선 대상이 바뀐 것 |
| 3 | **견본 자막 ID** `3293`(대사) · `4211`(나레) | 같은 번호에 같은 자막이 있다 |
| 4 | 그 견본의 **Source Text 파라미터** `3267` · `4185` | 같은 번호 · 블롭이 같은 글자를 담고 있다 |
| 5 | **트랙 UID** V1·V2·V3·A1·A2·A3 | 6개 전부 같다 |
| 6 | **시퀀스 UID** | 같다 |
| 7 | **Source Text 블록 137개 · 폰트 14종** | 같다(폰트가 대체 서체로 바뀌지 않았는가) |
| 8 | **속성으로 찾기 재현** | 새 파일에서도 조립기의 `견본찾기` 가 같은 자막을 집어내는가 |

대조는 `서버/runner/도너_대조.py --전 도너/_도너시험.prproj --후 도너/_도너시험_저장.prproj` 가 8항목을 한 번에 찍는다(약 8초). 같은 파일 두 벌로 미리 돌려 **8항목 전부 OK** 를 확인해 뒀다 — 즉 불통이 나오면 그것은 프리미어가 바꾼 것이다.

**1~7 중 하나라도 깨지면** — 이 길(도너 직접 편집)은 종료하고 블롭 서식 쓰기로 돌아간다.
**8만 깨지면** 조립기 쪽을 고치면 되므로 길은 유효하다.

> 조립기는 이미 **견본을 번호가 아니라 속성으로 찾도록** 고쳐 놨다(2026-08-19, 아래 「코드 손질」). 그래서 항목 3·4가 어긋나도 곧바로 사망은 아니다 — 다만 어긋난다는 사실 자체가 「프리미어가 번호를 다시 매긴다」는 뜻이므로 기록한다.

### 1단계 — 실제 편집 (0단계 통과 시, 사람 약 20분)

**고칠 견본 자막 2개 — 실측한 시각**

| 견본 | 트랙 | **찾을 시각** | 화면의 글자 | 지금 | **바꿀 값** |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 나레 자막 | **V3** | **1:05 ~ 1:06**(65.8s~66.5s) | 「자리를 지킨..」 | 120px | **64px** · 세로 **932** |
| 대사 자막 | **V2** | **0:03 ~ 0:05**(3.8s~5.5s) | 「돈 준다면 할 거야?」 | 58px | **44px** · 세로 **932** |

1. `도너/볼케이노_FullTime_v26_b05_ppro-v45.prproj` 를 복사해 **`도너/도너_2판.prproj`** 로 둔다(원본은 그대로 보존).
2. 산돌구름을 켠 채 `도너_2판.prproj` 를 연다 → **프로젝트 패널의 시퀀스를 더블클릭**해 타임라인을 연다.
3. 재생 막대를 **1:05** 로 옮긴다 → **V3 트랙**에서 그 자리에 걸친 자막 클립을 **한 번 클릭**해 고른다. 화면에 「자리를 지킨..」 이 보이면 맞다.

7. 재생 막대를 **0:03** 으로 옮긴다 → **V2 트랙**의 자막 클립을 고른다(「돈 준다면 할 거야?」).

10. 알려 준다 → 나는 `규격.조립.도너.파일` 을 `도너_2판.prproj` 로 바꾸고 조립기를 돌려 **자기검증 24검사**를 본다. 통과하면 완성 prproj 를 열어 **눈으로** 크기·한 레인을 확인한다.

**되돌아갈 지점**: 원본 도너는 손대지 않는다. 이상하면 `규격.조립.도너.파일` 을 원본 이름으로 되돌리면 끝이다.

### 코드 손질 — **완료** (2026-08-19)

견본을 **ObjectID 로 못박는 대신 속성으로 찾도록** 바꿨다(`서버/runner/조립_prproj.py` 의 `견본찾기`·`딸린ID`).

| 견본 | 찾는 방법 |
| :-- | :-- |
| 자막 나레 / 대사 | **V3 / V2 트랙**을 훑어 Source Text 블롭의 **폰트가 규격 `자막.폰트.*.PS명` 과 같은** 첫 자막 |
| 컷 비디오 / 컷 오디오 / 나레 | **V1 / A3 / A2 트랙의 첫 아이템** |
| 사슬·서브클립·클립·레벨 필터 | 아이템에서 **따라가 얻는다**(번호를 적어 두지 않는다) |

못 찾으면 규격에 적힌 번호로 물러선다. 찾은 번호가 규격과 다르면 **화면에 알린다**(도너가 바뀌었다는 신호).
현재 도너로 재조립 — 찾은 번호가 규격 값과 전부 일치, **자기검증 통과**.

## 결론 — 되는 범위 / 남는 범위

| 하고 싶은 것 | 어떻게 | 코드 변경 |
| :-- | :-- | :-- |
| 자막 **크기** 바꾸기(나레 64·대사 44) | **검토 1** — 도너를 프리미어에서 고친다 | **0** (0단계 통과 시) |
| 자막 **위치** 한 레인으로(y 932) | **검토 1** — 같은 편집에서 | **0** |
| 큐 **전체**의 톤 강조(폰트·크기 다른 견본) | 도너의 다른 자막을 **견본으로 추가** | 작음(견본 목록·선택 규칙) |
| **한 큐 안에서 단어만 강조**(색·크기) | ← **여기만 남는다** | **블롭 StyleTable 쓰기 필요** |

**잔여는 하나뿐이다** — 「한 줄 안에서 단어만 다른 색·크기로」. 이것을 나중으로 미루면, 지금은 **코드를 거의 건드리지 않고** 크기·위치·큐 단위 톤까지 얻는다.
