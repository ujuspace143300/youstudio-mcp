# 블롭 서식 쓰기 전에 — 더 싼 길 두 개 검토 (2026-08-19)

지시: 5+① 묶음(prproj 자막 크기·위치·강조)을 하기 전에, **코드 변경이 적은 길**이 있는지 먼저 본다.
결론만 먼저: **검토 1은 될 가능성이 크지만 실측이 하나 남았고, 검토 2는 안 된다.** 잔여 범위는 「한 큐 안 단어 강조」 하나로 좁혀진다.

---

## 검토 2 — 강조: 도너의 기존 색 런에 배치하는 길 → **불가**

### 실측: 도너 자막 136개 전수

| 항목 | 실측 |
| :-- | :-- |
| 자막 총 | **136개**(V2·V3·V4) |
| 런 개수 | 1런 104 · 2런 24 · 3런 8 |
| **서식이 다른 런을 가진 자막** | **0개** |
| 큐별 크기 종류 | 58 / 94 / 102 / 108 / 117 / 120 / 121 / 157 px — **큐 단위로는 다양** |
| 큐별 폰트 종류 | SDGwanghwamun 79 · Cafe24Dangdanghae 17 · SourceHanSerifK-Bold 15 · SDKwangya 6 · SDGdMyeongjo 5 · SDCharisma 3 · SDBangkakbon 3 · SDComicStencil 2 — **8종 이상** |

**한 큐 안에서는 모든 런의 서식이 같다.** 크기(f1)·읽히는 StyleTable 필드(f2 색·f4·f5·f6·f8·f23·f24)가 런마다 동일했다.

```
item 4265: 「현금 」 102px 색[0,0,0] | 「50달러」 102px 색[0,0,0] | 「를 정직하게 지불한 뒤」 102px 색[0,0,0]
item 4076: 「마이클은 본격적인 」 94px | 「감금 근무」 94px | 「를 시작하고..」 94px
```

### 그런데 눈여겨볼 것 — **런은 이미 강조 단어 경계로 나뉘어 있다**

「현금 」/**「50달러」**/「를 정직하게…」 · 「믿기 힘든 뜻밖의 」/**「정규직 전직」**/「 찬스를..」 — 가운데 런이 정확히 강조 대상 단어다.
즉 **볼케이노도 우리와 같은 구조(런 분할)를 쓰지만, 시각적 차이는 우리가 읽는 필드에 없다.** 셋 중 하나다:
1. 색이 우리가 못 읽는 자리(스트로크·그라데·레이어 중복)에 있다 — **가능성 높음**(흰 자막인데 색이 [0,0,0]으로 읽힌다. 파싱이 미더운 값이 아니다),
2. 이 도너 편에는 실제로 강조가 없다(런만 나뉘어 있다),
3. 강조를 다른 장치(별도 텍스트 레이어)로 낸다.

**어느 쪽이든 결론은 같다** — 견본을 복제해 단어를 배치해 봐야 **보이는 차이가 안 생긴다**. 배치할 「색 런」이 없다.

### 다만 하나 건졌다 — **큐 단위 톤 변화는 코드 변경 0으로 가능**

도너에 크기 7종·폰트 8종의 자막 큐가 이미 있다. 조립기가 **견본을 하나만 쓰는 대신 여러 개를 골라 쓰면**, 큐마다 폰트·크기를 바꿀 수 있다(예: 평범한 줄은 SDGwanghwamun 58px, 힘주는 줄은 Cafe24Dangdanghae 117px).
- 되는 것: **줄 전체의 톤 강조**
- 안 되는 것: **한 줄 안에서 단어만 강조** ← 이것이 잔여 범위다

## 검토 1 — 크기·위치: 도너를 프리미어에서 직접 고치는 길 → **될 가능성 크나 실측 1건 남음**

### 원리

조립기는 도너 견본의 **서식·위치를 그대로 복제**하고 글자만 갈아 끼운다. 그러므로 **도너 자체의 견본 자막을 새 값으로 고쳐 두면 코드 변경 0으로 반영된다.**

| 바꿀 것 | 지금(도너) | 새 값(규격) |
| :-- | :-- | :-- |
| 나레 자막 크기 | **120px** | **64px** |
| 대사 자막 크기 | **58px** | **44px** |
| 두 자막의 세로 위치 | 각자 다름 | **y 932 한 레인** |

### 위험 — **프리미어 재저장이 ID를 바꾸는가는 아직 안 재봤다**

계단 2 「왕복 실험」은 **우리 코드로 풀고 다시 싸기**(gzip 왕복)였다. **프리미어에서 열고 저장하는 왕복은 한 번도 안 했다.** 규격 「조립.도너」는 견본을 **ObjectID 로 못박고** 있다(컷_비디오 647 · 자막_대사 3293 · 자막_나레 4211 …). 프리미어가 저장할 때 ObjectID 를 다시 매기면 **조립기가 통째로 깨진다.**

**그래서 먼저 잴 것(사람 30분)**: 도너 복사본을 프리미어에서 **아무것도 고치지 않고** 열었다가 다른 이름으로 저장 → 우리가 두 파일의 ObjectID·UID·견본 ID·트랙 UID 를 대조한다. 이게 통과해야 실제 편집을 시작한다.

### 사람이 할 절차서 (초안)

**0단계 — 무해 왕복 시험 (먼저·필수)**
1. 산돌구름 앱이 켜져 있는지 확인(폰트가 대체 서체로 박히면 도너가 오염된다).
2. `도너/볼케이노_FullTime_v26_b05_ppro-v45.prproj` 를 **복사**해 `도너/_도너시험.prproj` 로 둔다.
3. 프리미어에서 `_도너시험.prproj` 를 **더블클릭**해 연다. **아무것도 고치지 않는다.**
4. 파일 > 다른 이름으로 저장 → `도너/_도너시험_저장.prproj`.
5. 클로드에게 알린다 → 두 파일의 ID 대조 결과를 보고한다. **여기서 깨지면 이 길은 끝**이고 블롭 쓰기로 간다.

**1단계 — 실제 편집 (0단계 통과 시)**
1. `도너/볼케이노_FullTime_v26_b05_ppro-v45.prproj` 를 복사해 `도너/도너_2판.prproj` 로 둔다(원본은 그대로 보존).
2. 프리미어에서 연다 → 시퀀스를 연다.
3. **V3(나레 자막) 트랙에서 견본 자막 클립 하나**를 고른다 — 클로드가 알려 준 시각의 클립.
4. 그 클립을 클릭 → 창 > Essential Graphics(기본 그래픽) > 편집 탭.
5. **텍스트 크기**를 120 → **64** 로 바꾼다.
6. **정렬 및 변형**의 세로 위치를 **932** 로 바꾼다(가로는 그대로).
7. **V2(대사 자막) 견본 클립**에 같은 방식으로 크기 58 → **44**, 세로 위치 **932**.
8. 저장(Ctrl+S) 후 프리미어를 닫는다.
9. 클로드에게 알린다 → 조립기를 그 도너로 돌려 자기검증 24검사를 통과하는지 본다.

**되돌아갈 지점**: 원본 도너 파일은 손대지 않는다. 문제가 생기면 규격 「조립.도너.파일」을 원본으로 되돌리면 끝이다.

### 코드로 위험을 줄이는 작은 손질 (권고)

견본을 **ObjectID 로 못박는 대신 속성으로 찾게** 바꾼다 — 「V3 트랙의 첫 자막 아이템」·「폰트가 SourceHanSerifK-Bold 인 것」. 그러면 도너를 다시 저장해 ID 가 바뀌어도 조립기가 안 깨진다. 20줄 안쪽의 변경이고, 앞으로 도너를 손볼 때마다 값을 갱신하는 수고도 없앤다.

## 결론 — 되는 범위 / 남는 범위

| 하고 싶은 것 | 어떻게 | 코드 변경 |
| :-- | :-- | :-- |
| 자막 **크기** 바꾸기(나레 64·대사 44) | **검토 1** — 도너를 프리미어에서 고친다 | **0** (0단계 통과 시) |
| 자막 **위치** 한 레인으로(y 932) | **검토 1** — 같은 편집에서 | **0** |
| 큐 **전체**의 톤 강조(폰트·크기 다른 견본) | 도너의 다른 자막을 **견본으로 추가** | 작음(견본 목록·선택 규칙) |
| **한 큐 안에서 단어만 강조**(색·크기) | ← **여기만 남는다** | **블롭 StyleTable 쓰기 필요** |

**잔여는 하나뿐이다** — 「한 줄 안에서 단어만 다른 색·크기로」. 이것을 나중으로 미루면, 지금은 **코드를 거의 건드리지 않고** 크기·위치·큐 단위 톤까지 얻는다.

### 권고 순서

1. **사람**: 0단계 무해 왕복 시험(30분) → 클로드가 ID 대조.
2. 통과하면 **사람**: 1단계 도너 편집(크기·위치) → 조립기 자기검증 → prproj 눈 확인.
3. **클로드**: 견본을 속성으로 찾도록 손질(도너 재저장에 안 깨지게).
4. 단어 강조(블롭 쓰기)는 **그 뒤에 따로** — 필요성이 확인된 뒤에 한다. 도너의 강조 표현 방식(색이 어디 있는지)을 먼저 알아내는 게 순서다.
