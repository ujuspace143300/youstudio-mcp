# 이식 원칙 — 볼케이노에서 발전시켜 유스튜디오로 붙이기

> 사장님 방침 (2026-09-04): 앞으로도 볼케이노 MCP 프리셋으로 발전시키다가 유스튜디오 MCP 로 붙이는 작업을 반복한다.
> 린박스(프리셋 3호) 이식에서 실제로 겪은 비용을 근거로 세운 원칙. 어느 컴퓨터에서 이식하든 이걸 따른다.
> 관련: [[youstudio-is-home-mcp]] · [[principle-correct-over-fast]] · 스케치코미디 선례 `설계/프리셋_스케치코미디.md` · 린박스 `설계/프리셋_린박스.md`.

## 큰 그림

- **볼케이노 = 실험·검증터** (남의 MCP, 프리셋 자유롭게 못 붙임, 지인 PC 권한 문제).
- **유스튜디오 = 본진·배포처** (사장님 소유). 검증된 프리셋을 여기로 이식해 지인에게 연다.
- 볼케이노 프리셋은 내부 작업용으로 **그대로 두고**, 유스튜디오에 같은 이름 프리셋을 새로 만든다(역할이 갈려 안 헷갈림).

## 이식 전 미리 정할 것 4가지 (매 프리셋)

### ① 「베끼기」 허락 범위를 프리셋마다 확인·기록
볼케이노는 남의 서버다. 지금 방침은 «산출물 꼴만 베끼고 서버는 호출 안 함»(린박스 5.6절). 배포자 허락이 **이 프리셋**에 대한 건지 «볼케이노 방식 전체»인지 매번 확인하고, 허락 범위를 그 프리셋 설계에 한 줄로 남긴다. 나중에 «이것도 베껴도 됐나» 안 헷갈리게.
★볼케이노 서버를 런타임에 호출하는 형태로 만들지 않는다 — 남의 서버 의존이 남으면 지인 배포 목적이 깨진다.

### ② 갈라짐 타이밍 — 언제 스냅샷을 뜰지
유스튜디오에 붙인 뒤에도 볼케이노 쪽은 계속 큰다 → 또 갈라진다(린박스에서 키트 두 벌 합치기에 하루 씀). 그래서 **이식 시점을 미리 정한다**: «볼케이노에서 N편 완주해 안정되면 이식, 이후 볼케이노 개선은 다음 이식 때 몰아서». 수시로 조금씩 이식하지 않는다(갈라짐·충돌 비용이 큼).

### ③ 프리셋별 유료 키 목록
프리셋마다 필요한 키가 다르다(setup channel_needs 가 알려줌): 린박스=전사+Typecast · 뇌전구=EvoLink+Typecast · 인물형롱폼=7개 등. 지인은 **본인 키를 직접 발급**(사장님 키 절대 안 넘김). 서버 setup 이 «필요한 키 + 발급처»를 프리셋별로 안내하게 한다.

### ④ 프리미어 필요 여부 = 지인 진입 장벽
맥 사슬 프리셋(린박스 등)은 지인 PC 에 프리미어+CEP 확장이 필요하다. 순수 mp4 로 끝나는 프리셋(스케치코미디 등)은 불필요. 이게 지인 진입 장벽을 크게 바꾼다 — 설치 안내에 반영.

## ⑤ 개선 반영처 — 「일 두 번」을 없앤다 (사장님 2026-09-04)

볼케이노 키트와 유스튜디오가 따로 있으면, 개선 하나가 나올 때마다 양쪽에 반영해야 해서 **일이 두 번**이고 헷갈린다(한쪽만 반영되면 또 갈라진다). 그래서 반영처를 «어디서 쓰느냐»로 못 박는다:

- **아직 유스튜디오에 이식 안 된 부분**의 개선 → **볼케이노 키트에만.** 이식할 때 최신 키트가 통째로 딸려오니 유스튜디오에 따로 넣을 필요 없다. (수시 이식 안 함 — ②)
- **이미 이식된 부분**의 개선 → **유스튜디오가 정본.** 볼케이노에도 반영하되(그쪽 내부 작업이 계속되니), **어느 쪽이 진짜인지는 항상 유스튜디오**다. 제안이 «이미 이식된 단계»(예: lb_transcript)를 건드리면, 승격(볼케이노)과 유스튜디오 반영을 **한 지시로 묶어** 같이 시킨다 — 따로 하면 잊는다.
- 제안을 검토할 때 클로드가 먼저 판정한다: **이 개선이 건드리는 부분이 유스튜디오에 이식됐나?** 됐으면 «양쪽 묶어 반영», 안 됐으면 «볼케이노만». 그 판정을 승격 지시에 적는다.

★긴 눈: 유스튜디오가 완성돼 지인 배포가 자리 잡으면, 그 프리셋의 정본은 유스튜디오 하나가 된다. 볼케이노는 새 프리셋 실험터로만 남고, 검증되면 이식 — 그러면 「두 번」이 다시 「한 번」이 된다([[youstudio-is-home-mcp]]).

## ⑥ 지인 설치 = 한방설치 + 서버 자산 다운로드 (길 C · 사장님 2026-09-04)

지인에게 «파일 묶음»을 USB 로 주는 건 번거롭다(볼케이노는 한방설치라 없었다). 볼케이노처럼 **명령 한 줄 한방설치**로 간다:
- **코드(러너)** = GitHub 공개 저장소에서 받는다. 공개해도 안전 — 토큰 없으면 서버에 못 붙는다(-32001). 사장님이 이메일 허락 안 하면 못 쓴다.
- **자산(글꼴·아모르 부품 등 저작권물)** = 아무나 못 받게 **서버가 토큰 인증으로 내려준다**(`/asset/<preset>/...`, 대장 검사 그대로 태움). 이메일 허가제 하나로 코드+자산 다 통제된다.
- 지인은 토큰 하나로: 코드 받기 → 자산 받기(토큰) → venv·ffmpeg·프리미어 확인 → claude mcp add(설치도우미) → 끝.

★**공개 전 필수**: (a) 비밀 유출 검사 — 2026-09-04 윈도우 확인: 박힌 키 없음·.env gitignore. (b) **자산 분리** — 자산/ 134개가 git 추적 중이라 공개하면 저작권 글꼴 노출. 저장소에서 빼고 **git 히스토리에서도** 제거(재작성이라 위험 → 사장님 승인 후 실행). (c) 저장소 «공개» 전환은 사장님이 GitHub 에서 직접(자산 분리·검사 끝난 뒤).

## ★배포 직전 체크리스트 (클로드가 배포 시점에 상기시킨다)

새 프리셋을 지인에게 실제로 열기 **전에** 확인:

- [ ] **KV 실제 생성 + wrangler deploy** — LICENSES KV id 채우기(`wrangler kv namespace create LICENSES`). 사장님 컴퓨터(owner).
- [ ] **프리셋별 권한** — 발급 대장에 `허용프리셋` 칸 구현했나(인증 설계 문서). 지인마다 쓸 프리셋 지정.
- [ ] **러너 기기헤더** — run_*.mjs 가 authHeaders() 를 붙이나(지금 영화롱폼 dev 러너는 미적용).
- [ ] **지인 키 목록 + 설치 안내(아티팩트)** — 이 프리셋에 **지인이 본인 계정으로 발급할** 키(setup channel_needs)와 발급처 URL. 사장님 키는 꾸러미에 **절대 안 넣는다**(빈 채로 전달, 지인이 채운다). 실제 배포 URL·프리셋별 문구도 최신화.
- [ ] **프리미어 필요 여부** — 필요하면 설치 꾸러미에 프리미어깔기.py + 안내에 «프리미어 필요» 한 줄(맥 사슬 프리셋).
- [ ] **베끼기 허락 범위** 문서에 기록됐나(①).

★**노출 키(TODO 3건)는 배포 조건이 아니다.** 그 3건은 사장님이 **계속 쓰는** 키가 8월에 노출된 별개 보안 건이고, 바꿀지는 사장님 판단(계속 쓸 거면 안 바꿔도 됨). **지인 배포와 무관** — 지인은 어차피 본인 키를 발급해 쓰고, 사장님 키는 지인에게 가지 않는다. (2026-09-04 사장님 확인: 저 키는 내가 계속 쓰는 거라 안 바꾼다. 빈 채로 전달해 지인이 본인 걸 쓴다.)
