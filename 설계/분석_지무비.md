# 분석 단계 — 지무비 10편 해부 (설계, 실행 전)

작성 2026-08-18. 상태: **설계 보고 — 승인 후 실행.**

가족 프로세스의 **① 분석 단계(레퍼런스 채널 칼카피)** 첫 정식 실행이다(`가족인터뷰.md`). 결정(사용자): **가족 결과물과 비교하는 대신 원본(지무비 최근 10편)을 직접 해부한다.** `분석단계_강조학습.md` 의 과제도 여기에 흡수한다. **제미나이 멀티모달 강제 규칙의 첫 실전 적용 대상**이기도 하다.

## 왜 지금인가 — 정답지의 절반이 「남의 자」다

`정답지.json` 을 훑으면 값의 출처가 세 갈래다.

| 갈래 | 예 | 이번 분석 대상 |
| :-- | :-- | :-- |
| **가족 자로 잰 값 · 「검증 필요」 꼬리표** | 한 줄 자수(파커 1편) · 무자막 최장 6.23s · 클립당 자막 0.46~2.68 · 자막 크기 px · 문장 자수 30~40 · 조각 자수 11~24 · 어미 배합 · 나레 시간점유 0.46~0.57 · G-턴비 · 블록 평균 자수 · G-밀도 3.3~5.2 | **○ 전량 재측정** |
| **지침서 조문(수치 근거 없음)** | 겹침 0 · 같은 어미 연속 max 3 · `..!` 구간당 1 · **죽은시간 0.14(잠정, 우리가 임의 재보정)** | **○ 실측으로 확정** |
| **우리가 사고에서 만든 값**(2026-08-17~18) | 대사선행 0.1s · 대사커버율 0.95 · 잔류 · 원문일치 · 줄바꿈 · 나레커버율 · 나레단어일치 | **× 대상 아님** — 이미 우리 자로 쟀고 근거가 진단일지에 있다 |

즉 이번 작업의 정확한 목표는 **「남의 자로 잰 값 + 근거 없는 조문」을 우리 계측기로 다시 재서 정답지를 정본화하는 것**이다. 우리가 만든 게이트는 건드리지 않는다.

## 2. 측정 방법 배정

### (a) 기계 실측 — 우리 계측기로 잰다

**대상: 10편 전부.** 지무비 영상은 **완성 리캡**이므로 우리 파이프라인 단계를 그대로 돌리는 게 아니라, **계측기만 떼어 쓴다**. 새 러너 하나로 묶는다: `서버/runner/분석_계측.py`.

| 계측 | 도구 | 얻는 것 | 차원 |
| :-- | :-- | :-- | :-- |
| 기본 | `ffprobe` | 길이·fps·해상도·오디오 규격 | D2 |
| **컷 검출** | `ffmpeg -vf "select='gt(scene,0.3)',showinfo"` | 컷 경계 시각 → 밀도·길이 분포. score 분포로 하드컷/디졸브 갈래 추정 | D1 |
| 무음 스캔 | `silencedetect`(규격 「전사.무음스캔」 값 그대로) | 발화/무음 구조 · 죽은 시간 | D3 |
| **전사** | Speechmatics batch(ko) **단어 단위** | 나레·대사 단어 시각 → 턴 구조·문장 길이·어미 분포 | D3·D7 |
| **자막 변화 검출** | 2fps 프레임 추출 → 자막 영역(하단/중단) 크롭 → **프레임 해시 변화** | 자막이 바뀌는 시각 → 큐 수·큐 길이·간격·잔류·무자막 최장 | D4 |
| 덕킹 | `astats`(구간별 RMS) — 나레 구간 vs 그 외 | dB 차 | D9 |
| 효과음 후보 | 고역 대역 에너지 급변 검출 | 후보 시각(제미나이 판독과 대조) | D8 |

**나레/대사 갈라내기**: 전사만으로는 누가 말했는지 모른다. 두 축을 교차한다 — ① 자막 **화면 위치**(나레 레인 vs 대사 레인, (b)가 알려 준다) ② 목소리 연속성(나레는 한 사람·같은 톤). 애매하면 그 편은 D3 에서 제외하고 표본 수를 줄인다(정직하게 표본 표기).

**정밀도 한계(미리 적는다)**: 자막 변화 검출은 2fps 라 **±0.5s**. 큐 길이·간격 분포에는 충분하지만 「잔류」처럼 0.1s 급 값은 그 편만 10fps 로 다시 잰다.

### (b) 제미나이 멀티모달 — 화면을 봐야 아는 것

**강제 규칙 그대로**: 영상 **전체**를 제미나이가 직접 본다. 프레임 추출은 폴백이 아니라 **보조**(강조 판독용 크롭 이미지)로만 쓴다. 전달은 가족 방식대로 **사람이 AI Studio 에 원본을 첨부**한다(Q2 답 — Files API 안 씀).

**절차서 초안** (편당 1회, 10회 반복)

1. AI Studio → 새 채팅 → 모델은 멀티모달 최신(사용자 계정 기준) → **영상 파일 첨부**(1편).
2. 아래 **분석 지침서**를 붙여넣는다(파일: `분석/지무비/_프롬프트.md` — 10편 모두 같은 것을 쓴다. 지침이 바뀌면 이미 받은 편도 다시 돌린다).
3. 출력이 오면 **코드 블록의 JSON 만** 복사해 `분석/지무비/<슬러그>/gemini.json` 으로 저장.
4. 화면 캡처가 필요하다고 답이 말하면(강조 판독 실패 등) 그 시각을 적어 두었다가 (a) 의 프레임 추출로 보완한다.

**분석 지침서에 담을 것** (요지 — 전문은 실행 승인 시 작성)
- 답은 **JSON 하나**로만. 추측한 값에는 `"확신": "낮음"` 을 붙일 것.
- 자막: 나레/대사 레인의 **화면 위치(비율)** · 폰트 인상(굵기·세리프 유무) · 글자 크기(화면 높이 대비 %) · 색(HEX 근사) · 외곽선·그림자 · **한 큐 안에서 색·크기가 다른 부분(강조)의 단어와 그 이유**.
- 효과음: 들린 시각(±1s) · 종류 이름 · 무엇에 붙었는지(컷 전환/강조 단어/반전).
- 전환: 하드컷 외 전환(디졸브·플래시)이 쓰인 시각.
- 도입 30초·결말 60초의 **구조 요약**(장면 순서와 나레의 역할).
- 이 편의 **인상적인 장치 3가지**(자유 서술) — 규칙화 후보를 사람이 고르게.

### (c) 클로드 분석 — 종합해서 대역·규칙으로

- (a) 원자료 + (b) JSON 을 편별로 합쳐 `분석/지무비/<슬러그>/합본.json` 을 만든다.
- 차원마다 **분포**를 낸다(중앙·p25/p75·p10/p90·표본 수). 편차가 큰 차원은 대역을 넓히지 말고 **원인**을 적는다(예: 장르·러닝타임 차이).
- **대역 규칙**(제안): soft 게이트 = **p25~p75**, hard 게이트 = **p10~p90**. 표본이 10편이므로 p10/p90 은 사실상 최소·최대 — 그 점을 출처에 명시한다.
- 「무엇이 참이어야 하는가」로만 적는다(HARNESS §3). 방법은 적지 않는다.

## 4. 예상 비용·시간

| 항목 | 근거 | 추정 |
| :-- | :-- | :-- |
| Speechmatics 전사 10편 | 실측: 929s → 처리 16초. 리캡 편당 ~15분 가정 → 총 ~2.5시간 오디오 | 처리 **총 3분 안쪽** · 요금은 시간 비례(본편 1회의 **약 10배**, 대시보드 확인) |
| 컷·자막·오디오 계측 | 로컬 ffmpeg. 편당 프레임 2fps 추출이 가장 무겁다 | 편당 **2~4분** × 10 = **30분 내외** · 비용 0 |
| 제미나이 판독 | 사람이 AI Studio 에 첨부 → 응답 대기 | 편당 **5~10분**(업로드 포함) × 10 = **1~2시간**, 사람 시간 |
| 클로드 종합·문서화 | 분포 계산 + 지침 개정 | **1~2세션** |
| 저장 공간 | 영상 10편 + 프레임 | 수십 GB(로컬만, 저장소 제외) |

**비용을 줄이는 선택지**: 전사를 5편만 해도 D3·D7 의 대역은 나온다(표본을 정직히 5로 적는다). D5·D6(모양·강조)은 제미나이 몫이라 전사와 무관하다.

## 위험·미리 정할 것

| 위험 | 대비 |
| :-- | :-- |
| 10편의 **장르·길이 편차**가 크면 대역이 무의미해진다 | 편별 러닝타임·장르를 먼저 표로 보고, 튀는 편은 표본에서 빼되 **뺀 이유를 적는다** |
| 제미나이 판독이 편마다 다른 형식으로 온다 | 지침서에 **JSON 스키마를 못 박고**, 형식이 어긋난 편은 다시 요청 |
| 자막 변화 검출이 화면 전환·자막 없는 구간에서 헛짚는다 | 자막 영역만 크롭 + 변화 임계값을 1편으로 보정한 뒤 10편 적용 |
