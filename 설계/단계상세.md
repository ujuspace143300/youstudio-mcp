## 8단계 한눈에

| \# | step | 주된 실행자 | 하는 일 | jobs\_kind | 작업 폴더 |
| :---- | :---- | :---- | :---- | :---- | :---- |
| 1 | `probe` | 서버 | 원본 확인 — 길이·해상도·fps·오디오 | 없음 (argv 는 start 가 실행) | probe/ |
| 2 | `transcript` | runner | 전사 \+ 타임코드 | `transcribe` | transcript/ |
| 3 | `brief` | 외부 판정 | 전사 전문을 읽고 사건 목록 | `judge` | brief/ |
| 4 | `select` | 외부 판정 \+ 서버 | 쓸 구간 확정 (화면 판정 \+ 규격 계산) | `judge` | clips/ |
| 5 | `script` | 클로드 | 구간을 잇는 나레이션 집필 | 없음 (status `need_input`) | script/ |
| 6 | `voice` | runner | TTS. 실측 길이로 슬롯 확정 | `synthesize` | voice/ |
| 7 | `subtitle` | runner | 자막 타이밍 \+ 컷 타임라인 | `argv` | subtitle/ |
| 8 | `export` | runner | 프리미어 XML \+ SRT \+ 나레이션 음원 | `argv` | render/ |

작업 폴더 이름은 setup 이 이미 만드는 것과 일치시킨다 (select→clips/, export→render/). **2차 목표** — `render` 단계(완성 mp4)는 export 뒤에 추가한다. 지금은 만들지 않는다.

**응답 칸 두 개를 구분한다** — `measure[]` 는 runner 에게 "무엇을 재서 payload 어디에 넣어라" 하는 **지시 규칙**(볼케이노 문법). `metrics` 는 **단계가 뱉는 숫자**(HARNESS 4장). 아래 "지표(metrics)" 줄은 후자다. `do[]` 는 jobs **앞에** 실행하는 준비용 argv 다(볼케이노는 do 를 jobs 뒤에 돌리지만, 우리 argv 는 전사·판정의 **입력**을 만들므로 앞에 둔다). `write_files[]` 는 서버가 내용을 정해 runner 가 파일로 쓰는 것이다. metrics 는 나중에 우리실측.json 에 쌓이는 원천이다 — 게이트는 이 숫자를 정답지 대역과 비교한다.

## 단계별 상세

### 1\. probe

- 입력: start 가 argv 로 만들어 둔 `probe/probe.json` 내용 (payload 로 전달)  
- 검사: **오디오 트랙 없으면 hard\_fail** — 수리 지침 포함해 반려  
- 출력: 검증된 probe 요약을 carry 에 담는다 (duration\_s·width·height·fps·audio) — jobs 없음. ffprobe argv 는 start 가 이미 지시했다  
- 지표(metrics): 원본 길이(초) · 해상도 · fps · 오디오 유무  
- 게이트: 없음  
- next: transcript

### 2\. transcript

- 입력: 원본 경로 \+ probe\_summary (carry)  
- 처리: 두 번 부른다. **① 지시** — `do[]` 로 오디오 추출(argv: 규격.json 「전사.오디오추출」대로 16kHz 모노 mp3) → `jobs_kind: transcribe` 로 Groq 전사. 키는 `auth` 로 "GROQ\_API\_KEY 환경변수에서 읽어라" 위치만 지시한다 (서버 무보관). **② 결과 검사** — payload.asr(verbose\_json) 를 받아 발화 단위로 정리해 `write_files` 로 `transcript/transcript.json` 을 쓰게 한다  
- 제공자: **결정됨 (2026-08-15) — Groq whisper-large-v3-turbo.** 값은 규격.json 「전사」  
- 파일 상한: 규격.json 「전사.파일상한\_mb」. 추출 파일이 넘으면 멈추고 보고한다 — **분할 전사는 미정**  
- 출력: `transcript/audio.mp3` · `transcript/asr_raw.json`(원본 응답) · `transcript/transcript.json` — 발화 단위 \+ 시작·끝 타임코드  
- 지표(metrics): 발화 수 · 총 발화 길이 · 무음 비율  
- 게이트: 없음. 발화 0건이면 hard\_fail  
- next: brief

### 3\. brief ← 외부 판정

- 입력: transcript 전문  
- 왜 외주: 전사 전문이 대화 컨텍스트를 잠식한다 (단계와게이트.md 「판정을 어디서 하는가」)  
- 처리: `judge` job — 결과는 반드시 `brief/brief.json` 파일로 저장  
- 출력: 사건 목록 (순번·요약·시작\~끝·중요도)  
- 지표(metrics): 사건 수 · 사건당 평균 길이  
- next: select

### 4\. select ← 외부 판정 \+ 서버 계산

- 입력: brief \+ transcript \+ 원본 (장면 판정용 조각은 clips/ 에)  
- 왜 외주: **화면을 봐야 한다** — 장면 전환·인물 등장은 글로 알 수 없다  
- 서버가 하는 계산: 목표 길이 → 구간 총량 배분 → 창 크기 제한 → 점수 가중 (수치는 규격.json)  
- 출력: `clips/selection.json` — 확정 구간 목록 (in/out·역할·근거)  
- 지표(metrics): 구간 수 · 총 길이 · 평균 길이 · 원본 대비 비율 · 분당 블록 수  
- 게이트: **G-밀도 · G-반복**  
- next: script

### 5\. script ← 클로드가 대화 안에서

- 입력: selection \+ 나레이션 지침 (`스타일/영화롱폼/나레이션.md` 를 서버가 내려보냄)  
- 왜 대화 안: 짧고 창의적인 집필. 컨텍스트 부담이 작다  
- 서버는 `need_input` 으로 멈추고 지침만 내려보낸다  
- 출력: `script/script.json` — 나레이션 블록 (구간 사이 위치·본문)  
- 지표(metrics): 나레:대사 비율 · 블록 수 · 평균 자수  
- 게이트: **G-턴비**  
- next: voice

### 6\. voice

- 입력: script  
- 처리: `synthesize` job — TTS 제공자·보이스는 규격.json. 키는 서버가 auth 로 위치만 지시, 로컬에서 읽어 붙인다 (서버 무보관)  
- 출력: `voice/*.wav` \+ `voice/voice.json` (블록별 **실측** 길이)  
- 지표(metrics): 총 나레이션 길이 · 블록별 길이  
- **중요**: 실측 길이가 타임라인 슬롯을 결정한다. 추정 금지 (measure-never-predict)  
- next: subtitle

### 7\. subtitle

- 입력: script \+ voice 실측 \+ transcript  
- 출력: `subtitle/timeline.json` \+ `subtitle/subtitle.srt`  
- 지표(metrics): 자막 큐 수 · 분당 큐 밀도 · 한 줄 최대 자수 · 겹침 수 · 죽은 시간 비율  
- 게이트: **G-자막 · G-죽은시간**  
- next: export

### 8\. export

- 입력: timeline \+ voice \+ 원본  
- 출력: `render/` 에 프리미어 교환 XML · subtitle.srt · 나레이션 음원 · manifest.json  
- **prproj 직접 생성은 하지 않는다** (참고 코드 7,856줄 — 포기 결정). XML 형식은 미정 (가족 인터뷰 항목)  
- 지표(metrics): 컷 수 · 평균 컷 길이 · 총 길이  
- 게이트: 1\~7 의 게이트를 최종 산출물에 다시 적용 (전체 재검사)

## 게이트 5개

원칙 (단계와게이트.md 와 일치):

- 산출물에서 **독립 계산**. 판정 파일을 신뢰해 통과시키지 않는다  
- 조건은 **대역**으로. 방법을 지시하지 않는다  
- 불통 메시지에 **반드시 수리 지침** — 수리는 항상 "규격.json 의 무엇을 어떻게" 형태  
- 표본 부족이면 soft (경고만)

대역 값은 `스타일/영화롱폼/정답지.json` 에 둔다 (지무비 19편 정본 — 단계와게이트.md 「대역 수치」).

| 게이트 | 검사 | 시점 | 정답지 근거 (참고\_게이트.md) | 수리 지침 예 |
| :---- | :---- | :---- | :---- | :---- |
| G-밀도 | 분당 블록 수 | select 후 | G25 (3.3\~5.2s 블록 등) | "블록이 성기다 → brief 의 중요도 상위 사건을 추가 선택" |
| G-반복 | 구간 재사용·연속 컷 | select 후 | G16·G13 | "중복 상위 N개를 제거하고 미사용 사건으로 대체" |
| G-턴비 | 나레:대사 비율 | script 후 | G26 (0.55\~1.06)·G28 | "나레 과다 → 설명 블록을 원본 대사로 교체" |
| G-자막 | 한 줄 자수·겹침 | subtitle 후 | G3·G1 (겹침 0\) | "초과 큐 목록 제시, 각각 분할 또는 축약" |
| G-죽은시간 | 무음·정체 비율 | subtitle 후 | G14 | "죽은 구간 상위 N개 위치 제시, 잘라내거나 당겨 붙임" |

hard\_fail (게이트 아님 — 단계 진입 조건): 오디오 트랙 없음 / 발화 0건 / 판정 결과 파일 부재 / TTS 생성 실패.

**hard\_fail = `status: "error"` 반려.** 응답 status 어휘에 hard\_fail 은 없다. 서버는 `status:"error"` · `next_step` 은 같은 단계 · `message` 와 `instructions` 에 수리 지침을 담아 돌려준다.
