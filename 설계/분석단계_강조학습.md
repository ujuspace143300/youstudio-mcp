# 분석 단계 — 자막 강조점 학습 (과제 등록, 입력 대기)

> **2026-08-18: 이 과제는 `설계/분석_지무비.md` 의 차원 **D6(자막 — 강조)** 로 흡수됐다.** 측정 방법·산출물은 그 문서를 따르고, 이 파일은 **왜 필요한가·무엇을 만들 것인가**의 근거로 남는다.

등록 2026-08-17 (사용자 결정). 상태: **입력 대기** — 사용자가 지무비 영상 원본 여러 편을 주면 시작한다. 이것은 가족 프로세스의 **「① 분석 단계 — 레퍼런스 채널 칼카피」의 첫 실전 사례**다(`가족인터뷰.md`). 지금 판(전체본)은 **B안**으로 간다: 텍스트를 **단어 경계에서만** 런에 나눠 어색한 중간 끊김을 막고, 강조가 우연히 어디 붙는지는 **일단 허용**.

## 왜 필요한가

프리미어 자막 한 큐는 **런(run)** 여러 개로 쪼개져 있고, 런마다 폰트·크기·색을 따로 준다 — 지무비/볼케이노가 **한 큐 안에서 특정 단어만 크게·다른 색으로** 강조하는 장치가 이것이다(볼케이노 완성본 실측: 나레 자막이 2~3런, 톤 폰트 8종 혼용 — `참고_export.md` 9-2). 우리는 지금 **런을 기계적으로 나누기만** 하므로 강조가 의미와 무관한 자리에 붙는다. 어느 단어를 강조할지는 **판단**이고, 판단 근거는 레퍼런스에서 배워야 한다(HARNESS 「보이지 않으면 존재하지 않는다」).

## 입력 (사용자가 줄 것)

- 지무비 롱폼 리캡 **영상 원본 여러 편**(자막이 화면에 보이는 완성본). 편수는 많을수록 좋고, 최소 5편·가능하면 19편(정답지 표본과 같은 편들).
- 있으면 좋은 것: 그 영상들의 자막 텍스트(SRT/대본). 없으면 화면에서 읽는다.

## 산출 (무엇을 만들 것인가)

| 산출 | 내용 |
| :---- | :---- |
| `스타일/영화롱폼/강조.md` | 강조 규칙 지침(사람이 읽는 말) — 무엇을 강조하고 무엇을 강조하지 않는가 |
| `정답지.json` 「자막.강조」 | 대역 — 큐당 강조 런 수 · 강조 글자 비율 · 색 종류 수 · 크기 배수 |
| `규격.json` 「자막.강조」 | 우리 설정값 — 강조 색·크기 배수·폰트(톤 폰트 쓸지) · 큐당 상한 |
| `timeline.json` 큐의 `emph` 필드 | 큐마다 강조 구간 [시작 글자, 끝 글자] 목록 — subtitle 단계가 채운다 |
| script/subtitle 단계 규칙 | 대본을 쓸 때 강조 후보를 표시하고, 자막 단계가 런 분할을 그 경계로 맞춘다 |

## 분석 방법 (초안 — 입력 받으면 확정)

1. **표본 수집**: 영상에서 자막이 바뀌는 시점을 프레임으로 잡고, 큐마다 화면을 저장한다(ffmpeg). 자막 영역만 잘라 낸다.
2. **판독**: 제미나이 멀티모달에 큐 이미지를 주고 「이 자막에서 색·크기가 다른 부분은 어디이고 무슨 단어인가」를 구조화 출력으로 받는다(brief 와 같은 responseSchema 방식). 판독이 애매하면 사람이 확인.
3. **패턴 뽑기**: 강조 단어를 품사·의미 유형(숫자·고유명사·감정어·반전어·의성어…)으로 분류하고, 큐당 강조 개수·강조 글자 비율·색/크기 조합의 **대역**을 낸다.
4. **규칙화**: "무엇이 참이어야 하는가"로 적는다(HARNESS 3) — 예: 「큐당 강조 런 ≤ n」 「강조 글자 비율 x~y」 「숫자·금액은 강조 후보」.
5. **인코딩**: 위 산출 표대로 파일에 넣고, 게이트(강조 비율 대역·큐당 상한)를 subtitle 단계에 붙인다.
6. **검증**: 우리 산출물의 강조 분포가 대역 안에 드는지 + 사람 눈으로 한 편 비교.

## 지금 판(B안)과의 관계

- 지금: `prproj_lib.split_runs_words` 가 단어 경계에서만 나눈다 → 런 경계가 단어를 자르지 않는다. 강조 서식 자체는 도너 견본 값 그대로라 **모든 런이 같은 서식**이다(=강조가 눈에 띄지 않는다).
- 다음 판: `emph` 필드가 생기면 런 경계를 **강조 구간 경계**로 맞추고, 그 런에만 규격 「자막.강조」 서식(색·크기)을 준다. 블롭 조작은 이미 검증된 tail relocation 위에 **StyleTable 의 크기(f1)·색(f2) in-place 쓰기**를 더하는 일이다(`참고_prproj구조.md` 4절, 가족 `textblob.py` 지식).
