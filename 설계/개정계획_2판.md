## 1. 얽힌 항목 — 따로 고치면 깨진다

```
  나레 글자 크기 ↓  ──→  한 줄 자수 상한 ↑  ──→  줄바꿈 규칙(집필 lines[])
        │                      │                        │
        └──────→ 자막 레인 하나로 합치기 ←───────────────┘
                        │
                  교차겹침·커버율 게이트 재측정
```

- **크기 ↔ 자수 ↔ 줄바꿈은 한 세트다.** 글자를 줄이면 한 줄에 더 들어가므로 `자막.나레_한줄_최대자수`(지금 18)를 다시 정해야 하고, 그러면 집필자가 나눈 `lines[]`가 전부 다시 나뉘어야 한다(대본 재집필은 아니고 줄 나눔만 — 음성 재합성 없음).
- **레인 합치기**는 크기 결정 뒤에 한다. 같은 자리에 두 종류가 오가므로 크기·색이 구분의 유일한 수단이 된다.
- **밀도 3종**은 select·script 단계라 자막과 독립이다 — 병행 가능.

### 실행하며 드러난 사실 두 가지 (계획서에 없던 것)

**ⓐ 크기·위치 변경은 본선 prproj 에 반영되지 않는다.** ~~(2026-08-19 정정 — 아래 §7 참조: 도너를 프리미어에서 고치니 코드 변경 0으로 반영됐다)~~
조립기는 도너 자막의 **서식·위치를 그대로 복제**하고 글자만 갈아 끼운다(`조립_prproj.py` — 블롭에서 텍스트만 tail relocation). 따라서 규격 `자막.크기_px`·`자막.위치` 는 **FCP XML 폴백과 manifest 안내에만** 반영된다.
→ prproj 겉모습을 바꾸려면 **블롭 StyleTable 의 크기(f1)·색(f2) 쓰기**가 필요하고, 이는 **5단계(강조 도입)와 같은 기술**이다. 두 작업을 **묶어서** 하는 것이 맞다(따로 하면 블롭 서식 쓰기를 두 번 만든다).

**ⓑ 나레 큐 수는 자수가 아니라 「나레 음성의 쉼」이 정한다.**
줄을 74 → 56 으로 줄였는데 **나레 큐는 74개 그대로**다. 줄이 길어지자 그 줄이 발성 덩어리 두 개에 걸쳤고, 규칙에 맞는 자리에서 다시 쪼개졌기 때문이다(그 쪼갬은 `G-나레커버율`·`G-자막음성일치` 를 지키려는 정상 동작이다).
→ **분당 큐를 레퍼런스(14.6)에 가깝게 만들려면 자수가 아니라 TTS 의 쉼 구조를 바꿔야 한다** — 문장을 길게 쓰거나(대본), 합성 때 쉼을 줄이거나(음성). 7단계(밀도) 에서 다룬다.

### 남은 것

- prproj 겉모습(크기·위치·강조) → **5단계와 묶어서** 블롭 서식 쓰기로.
- 분당 큐 밀도 → **7단계**(대본·TTS 쉼 구조).

## 7. 정정과 마무리 — ①②④ 는 본선 prproj 에 들어갔다 (2026-08-19)

§6 ⓐ 에서 「prproj 겉모습을 바꾸려면 블롭 StyleTable 쓰기가 필요하다」고 적었다. **틀렸다.**

| 무엇 | 어떻게 | 결과(실측) |
| :-- | :-- | :-- |
| ① 나레 글자 크기 | 도너 견본을 프리미어에서 120 → 64px | 나레 큐 **74개 전부 64px** |
| ② 대사 글자 크기 | 58 → 44px | 대사 큐 **140개 전부 44px** |
