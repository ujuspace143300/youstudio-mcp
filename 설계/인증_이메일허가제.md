# 인증 — 이메일 허가제 (발급 대장) 설계

> 상태: **설계 확정 대기 값 2개**(만료 기본값·기기 초과 시 동작) 남음. 나머지는 사장님 2026-09-03 결정으로 확정.
> 이 작업은 **프리셋 이식과 독립**이다 — 린박스 키트 합치기를 기다리지 않고 먼저 만들 수 있다.
> 대상 코드: `서버/src/index.ts`(인증), 새 파일 `서버/src/auth.ts`(대장), Cloudflare **KV**(대장 저장).

## 왜 (사장님 2026-09-03)

- 유스튜디오는 사장님 소유 서버라 지인·외부에 열어준다. 그러려면 **누가 쓰는지 구분**하고 **개별로 끊을** 수 있어야 한다.
- 지금 인증은 단일 토큰 `YOUSTUDIO_TOKEN`(index.ts) — 아는 사람 전부 통과, 만료 없음, 개별 차단 불가. 배포에 못 쓴다.
- **Cloudflare Access 는 안 쓴다.** Access 의 이메일 OTP 는 사람이 브라우저에서 코드를 넣는 방식인데, 유스튜디오는 클로드코드(프로그램)가 `Authorization: Bearer` 헤더로 붙는 연결이라 이메일 경험이 안 나오고 결국 서비스 토큰이 된다(지금과 동일). 50명 초과 시 유료 위험도 있다. → 서버 안에 **직접 만든 발급 대장**이 더 싸고(0원) 사장님 그림에 정확하다.

## 사장님이 그리는 프로세스 (이대로 됨)

1. 사장님이 **허락할 이메일을 대장에 등록** → 서버가 그 이메일 전용 토큰을 발급.
2. 지인은 그 토큰으로 유스튜디오 MCP 를 붙인다(설치 안내에 「토큰을 여기 넣으세요」).
3. 사장님은 대장에서 **이메일 목록 보기 / 한 명 끊기 / 기기 풀기 / 연장**.

## 대장 한 줄의 모양 (Cloudflare KV, 키 = 토큰)

```
이메일:      친구@example.com
토큰:        (발급 시 랜덤 32바이트)
발급일:      2026-09-03
만료일:      2026-12-02              ← 만료 지나면 서버가 거부
허용대수:    2                       ← 이메일당 기본 2대 (지인별로 1·3 도 가능)
등록된기기:  [지문A, 지문B]           ← 처음 비었다가 붙을 때마다 채워짐. 초과분은 거부
막힘:        false                    ← 사장님이 즉시 차단하고 싶을 때 true
```

## 서버가 요청마다 하는 검사 (index.ts authorized 확장)

순서대로, 하나라도 실패하면 401 + 이유:
1. 헤더의 Bearer 토큰이 **대장에 있나** (없으면 «등록되지 않은 토큰»)
2. `막힘 == false` (true 면 «차단된 계정 — 사장님에게 문의»)
3. **만료일 안 지났나** (지났으면 «토큰 만료 — 사장님에게 연장 요청»)
4. **기기 지문** — 요청 헤더의 기기 지문이 `등록된기기` 에 있으면 통과. 없으면:
   - 빈 자리 있음(`등록된기기.length < 허용대수`) → 등록하고 통과
   - 자리 없음 → 거부 «등록된 기기 N대를 초과했습니다 — 사장님에게 기기 초기화 요청»

★기기 지문은 지인 러너가 붙일 때 헤더(예: `X-Youstudio-Device`)로 보낸다. 값 = 그 컴퓨터의 안정된 고유값(설치 시 한 번 만들어 `~/.youstudio/device` 에 저장하는 랜덤 id — 하드웨어 값이 아니라 **설치 id**라 포맷하면 바뀐다. 그게 자연스럽다: 포맷=새 기기).
★키 값(YOUSTUDIO_TOKEN·API 키)은 **절대 대장·로그·payload 에 평문 저장 안 한다**는 기존 규칙 유지. 토큰은 대장의 KV 키 자체이고, 비교만 한다.

## 사장님 관리 (발급·차단·연장) — 방식 미정, 둘 중

- **(a) 관리 명령** — 사장님 컴퓨터에서 `node 서버/도구/대장.js 발급 <이메일>` / `막기 <이메일>` / `풀기 <이메일>` / `연장 <이메일> <일수>` / `목록`. 빨리 만든다(반나절). 지금 단계 추천.
- **(b) 관리 웹페이지** — 사장님만 여는 페이지에서 이메일 목록·버튼. 나중에 (a) 위에 얹는다.

## 확정값 (사장님 2026-09-03)

1. **만료 기본값 = 90일** ✔ (연장은 사장님이 대장에서).
2. **기기 자리 꽉 찼을 때 = 거부 → 사장님이 대장에서 푼다** ✔ (자동 밀어내기 안 씀 — 공유 방지 우선).
3. **허용대수 = 기본 2대, 상한 50** ✔ (A안, 2026-09-03). 지인은 기본 2대(데스크탑+노트북). 특별한 사람만 사장님이 대장에서 최대 50까지 올린다. 원취지(오남용·공유 방지) 유지하면서 여유만 크게.

## 프리셋별 권한 (★구현됨 2026-09-04 맥2 a149866 — 아래 설계대로: License.presets · decideAuth 6번째 검사 −32007 · index.ts 가 body 의 tools/call arguments.preset 을 넘김(배치면 전부) · 대장.js 발급 --프리셋 / 프리셋추가 / 프리셋빼기 · test/auth.mjs 27항목 · 로컬 KV 로 HTTP 검증(허용 execute·미허용 −32007·initialize 통과·기기 없음 −32005))

이메일별로 **어느 프리셋을 쓸 수 있는지** 따로 준다. 지인 A=린박스만, 지인 B=린박스+스케치코미디 식.

- 대장 한 줄에 칸 하나 추가: `허용프리셋: ["린박스", ...]` (빈 배열/누락 = 전부 허용? 아니면 전부 거부? → **기본 = 전부 거부**, 명시한 것만 허용. 안전한 쪽).
- auth.ts decideAuth 에 6번째 검사: 요청의 preset 이 `허용프리셋` 에 있나. 없으면 거부(-32007 «이 프리셋은 권한이 없습니다 — 관리자에게 요청»). ※preset 은 도구 인자라 요청 body 에서 꺼내야 한다 — index.ts 에서 MCP 요청을 파싱해 preset 을 decideAuth 에 넘기는 배선 필요.
- 대장 도구(대장.js)에 `프리셋추가 <토큰> <프리셋>` · `프리셋빼기 <토큰> <프리셋>` 명령.

**왜 지금 구현 안 하나:** 아직 유스튜디오 프리셋이 린박스 하나(이식 중)라 프리셋 권한을 시험할 대상이 없다. 프리셋이 2개 이상 되고 실제 배포할 때 넣는다(한 번에 하나씩). ★배포 직전 체크리스트(아래 이식원칙 문서)에 이 항목이 있다 — 클로드가 배포 때 상기시킨다.

## 하지 않을 것

- Access·외부 인증 서비스 도입 안 함(위 이유).
- 사장님 API 키를 지인에게 전달 안 함 — 지인은 **본인 키를 직접 발급**(유료 포함). 서버 setup 이 「필요한 API + 발급처」만 안내한다(값은 안 받음).
- 기기 지문에 하드웨어 식별자(맥주소·시리얼) 안 씀 — 사생활·불안정. 설치 id 로 충분.
