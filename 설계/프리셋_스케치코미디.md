## 1. 무엇을 만드나 — 소재 → 산출물

**스케치 코미디 롱폼(유튜브)을 잘라 40~50초(최대 75) 숏폼 mp4 로 만든다.** 나레이션(건조한 제3자 톤)이 핵심 장치, 구조는 5-Phase(Hook→Context→Ping-Pong→Climax→Punchline).

영화롱폼과 **산출물도 단계도 다르다** — 카드 4절이 예고한 "단계 순서가 다른 프리셋"의 첫 사례다.

| | 영화롱폼 | **스케치코미디** |
| :-- | :-- | :-- |
| 소재 | 로컬 영상 파일 | **유튜브 URL** (yt-dlp 다운로드) |
| 산출물 | `.prproj` (사람이 프리미어에서 마무리) | **완성 mp4** (ffmpeg 직접 렌더) |
| 편 수 | 소재당 1편 | **소재당 2편 (A/B)** |
| 대본 | 나레이션 집필 (클로드) | **원본 컷 계획 + 나레 1~2문장** (멀티모달 판정) |
| TTS | ElevenLabs eleven_v3 | **Typecast Gowoon** (toneup · vol 100 · 실측 0.161초/자) |
| 전사 | Speechmatics (전체 전사) | Speechmatics (**자막 싱크용 — 시각만 쓰고 문구는 안 쓴다**) |
| 멀티모달 | select 프레임 판정 | **EvoLink 우선, 순정 Gemini 폴백** (`gem.py`) |

규격 정본은 「마스터 지침서 3.11」이고 `config.json`(310줄)이 그 전사본이다. **재해석하지 않는다** — 값을 그대로 옮긴다. ★지침서 원문 파일 위치는 사장님 확인 대기(전사본으로 진행은 가능).

## 2. 단계 — sketch2 흐름을 MCP step 으로 편다

sketch2 흐름(`_flow`): `plan → check → render → subs → asr → sync → check → render` (+comments).
루프(검사·렌더 2회)를 **선형으로 편다** — STEP_ORDER 는 "다음 칸" 상태 기계라서다.
자막을 두 번 뽑는 이유: 계획 자막은 원본 전체 기준이라 성기고, 잘라 붙인 `cut.mp4` 기준으로 다시 봐야 맞는다. 1차 렌더는 `cut.mp4` 를 만들기 위한 것(TTS 캐시로 2차에서 재과금 없음).

| # | step | 하는 일 | 실행 주체 | 요금 |
| :-- | :-- | :-- | :-- | :-- |
| 0 | `setup` | (공통) ffmpeg·작업 폴더·규격 전달 | 서버 | |
| 0 | `start` | 소재 = **유튜브 URL** 접수 · A/B slug·focus 접수 | 서버 | |
| 1 | `sk_plan` | 원본 다운로드(yt-dlp) + 5-Phase 계획 + 제목 후보 5·후킹 대사 3·댓글 선택 → 편.json | 러너 `plan` | EvoLink 무료 한도 |
| 2 | `sk_check` | **구조 게이트 판정** (아래 5장) — 반려면 계획 수정 후 재판정 | **서버** | 공짜 |
| 3 | `sk_cut` | 1차 렌더 — cut.mp4 + 나레이션 TTS | 러너 `render` | ★**TTS(Typecast)** |
| 4 | `sk_subs` | 자막 재추출 — cut.mp4 만 본다 | 러너 `subs` | EvoLink |
| 5 | `sk_asr` | 실제 발화 시각 실측 | 러너 `asr` | ★**Speechmatics** |
| 6 | `sk_sync` | 자막 시각을 발화에 맞춤(줄 단위) — **맞물림 25% 미만이면 중단** | 러너 `sync` | 공짜 |
| 7 | `sk_recheck` | 대본이 바뀌었으니 게이트 재판정 | **서버** | 공짜 |
| 8 | `sk_render` | 2차 렌더 = 완성본 (TTS 캐시 재사용) | 러너 `render` | 공짜 |
| 9 | `sk_deliver` | 완성 검사 목록 + 사람 확인 항목(첫 3초 훅·나레 겹침·칼종료) 안내 | 서버 | |

- 접두사 `sk_` 로 영화롱폼 step 과 충돌을 피한다(볼케이노가 `shop_`·`person_` 으로 하는 방식). step enum 은 합집합.
- A/B: `start` 에서 slug 를 받아 **한 편씩 완주**한다. B 편은 `--focus <초>` 로 다른 클러스터.
- comments 재선택(`--refetch`)은 별도 step 을 만들지 않는다 — `sk_deliver` 가 필요 시 안내.

## 3. 선행 작업 — 파이프라인 등록표 (카드 4절 ①)

지금 서버는 STEP_ORDER 하나 + `steps/*.ts` 가 영화롱폼 상수를 직접 import 한다. 전환:

1. `Style` 에 **단계 배열**(그 프리셋의 step 순서)을 넣고, next_step 을 프리셋의 배열에서 뽑는다
2. step enum 은 등록표의 합집합으로 파생 (`schema.ts` 손대지 않는 원칙 유지)
3. 영화롱폼 쪽은 **한 단계씩** 상수 import → 등록표 참조로 전환, 단계마다 스모크(141항목) 회귀 통과 확인
4. 인증 사용자별 전환(카드 4절 ②)은 **외부 배포 전 조건**이라 이번 범위 밖 — TODO.md 에 이미 있다

## 5. 게이트 — 정답지로 갈 것 (make.py check 실증 목록)

| 게이트 | 대역 | 성격 |
| :-- | :-- | :-- |

| **밀도** (완성 ÷ 원본 펼친 범위) | **35~80%** (100% 초과 = 겹침 신호) | ★★★반려 — 완성도를 가장 크게 가른다 |
| 조각 겹침 | > 0.05초 없음 | 반려 |

| 훅 세기 | 첫 조각 punch ≥ 8 | 반려 |
| Climax 위치 | 전체의 ≥ 60% 지점 | 반려 |
| Phase 몫 | 한 칸이 지침서 몫의 3.5배 초과 금지 | 반려 (2.2배는 실측으로 과함) |
| 나레이션 | 20자(≈3초) 이내 · **패딩**(화면 ≥ 읽기시간) · **P1·P5 금지** · 1~2개 권장 | 반려/주의 |
| 제목 | 2줄 · 줄 15자 이내 · 끝 `?` `!` `...` · 후보 5개 | 반려/주의 |
| 자막 | 3초 이상 빈 구간 없음 · 한 줄 자수 상한 | 주의 |
| 싱크 | ASR 맞물린 글자 ≥ 25% (미만이면 중단·`subs_before_sync` 보존) | 중단 |
